build_from_bytes with an elevation raster: the bytes of a GeoTIFF file, as build_from_dir reads the .tif file of a directory. The slope costs of BuildOptions::elevation are applied to walking and cycling (with Elevation::None the raster is not read). Errors about the raster name it elevation raster.

The raster must be a GeoTIFF of one band of 8, 16 or 32-bit integers or 32 or 64-bit floats, uncompressed or compressed with LZW, Deflate or PackBits, north up, georeferenced by a tie point and a pixel scale (what GDAL writes), in WGS 84 longitude and latitude (EPSG:4326) or in another system whose coordinate transform peabiru computes itself: SIRGAS 2000 (4674), SAD69 (4618), Corrego Alegre 1970-72 (4225), their UTM zones used in Brazil, SIRGAS 2000 / Brazil Polyconic (5880), WGS 84 / UTM (326xx, 327xx) and WGS 84 / Pseudo-Mercator (3857). Other rasters are an error that says what to change. In a system other than EPSG:4326, the pixel read for a sample within nanometres of the boundary between two pixels of different values (or of the raster’s edge) depends on the last bits of the projection’s sines and cosines; peabiru computes them itself, bit for bit the same way, so it reads the same pixel on every machine, and counts such samples in StreetNetwork::elevation_warnings (and so in Network::build_warnings). A sample that falls on the outer edge (inside the envelope, past the last pixel) is an error.
