Expand description

Build a network from data held in memory: the bytes of an OpenStreetMap .pbf file and of any number of GTFS .zip feeds, each with its file name. The network is the one build_from_dir builds from a directory holding the same files, and the stops are linked to the streets in the same way.

The feeds are loaded in the order of feeds. That order matters: the stops, patterns and, where two feeds offer equally good trips, the routes chosen follow it. build_from_dir loads them in the order the operating system lists the directory, which differs from one file system to another; to reproduce a network built from a directory, pass the feeds in the order of its TransitLayer::feed_reports.

A feed’s name stands for its file name: it names the feed in errors and in FeedReports and, when the feed has no feed_info.feed_id, gives its feed id (the name without a trailing .zip), which prefixes its stop ids. Use the names the files have on disk (such as "poa_eptc.zip") and keep them distinct. Errors about the .pbf data name it OpenStreetMap data. With no feeds, the network has no public transport, good for street routing only.

The build fails when a feed has GTFS errors of priority HIGH, or is one gtfs-lib cannot load at all (NetworkError::high_priority_gtfs_errors, gtfs_errors), unless BuildOptions::ignore_gtfs_errors is set.

let pbf = std::fs::read("r/inst/extdata/spo/spo_osm.pbf")?;
let gtfs = std::fs::read("r/inst/extdata/spo/spo_gtfs.zip")?;
let opts = peabiru_core::BuildOptions::default();
let network = peabiru_core::build_from_bytes(&pbf, &[("spo_gtfs.zip", &gtfs)], &opts)?;
assert_eq!(network.transit().unwrap().feed_ids(), ["spo_gtfs"]);
