Struct CsvOutput

Expand description

Writes routing results to a directory, one CSV file per origin.

Each origin’s table is saved to a file of its own as soon as the origin is routed, and nothing is kept in memory:

  • the file is <output_dir>/from_<origin id>.csv (plain concatenation, the id is not sanitized), written only when the origin has at least one row, replacing a file of the same name;
  • a header with the column names joined by ,, then one line per row, each ended by the platform’s line separator (\n, \r\n on Windows);
  • a field holding ,, ", \n or \r is quoted, with " doubled; a missing value is an empty field;
  • integers are written in decimal, doubles with at least one decimal and, below 0.001 or from 10,000,000, with an exponent (0.0, 2.1, 1.0E-4).

The values are the tables as routed, with nothing done to them afterwards: the WALK origin/destination swap is not made, and the accessibility cutoff column is kept with fixed_exponential (the placeholder 0).

The routing functions return whole matrices; to keep memory bounded, route the origins in the slices that CsvOutput::origin_chunks gives and write each matrix before routing the next slice.

The ids are those of all the origins and destinations of the call; each write_* method takes a matrix routed from a slice of the origins that starts at first_origin.

impl<'a> CsvOutput<'a>

Source

pub fn new( dir: &str, origin_ids: &'a [String], destination_ids: &'a [String], n_threads: usize, ) -> Result<Self, RouteError>

A writer to directory dir, which must exist, for the origins and destinations with these ids (the destination ids are not used by write_accessibility). Files are written by n_threads threads (0 = all cores).

The files are named after the origin ids, so an id that cannot be part of a file name in dir (one holding a path separator / or \, or NUL; on Windows also < > : " | ? * or a control character) is RouteError::Invalid, before anything is routed or written.

Source

pub fn path(&self, origin: usize) -> String

The path of the file of origin origin: <dir>/from_<id>.csv.

Source

pub fn origin_chunks( &self, values_per_origin: usize, ) -> impl Iterator<Item = Range<usize>>

The origins in consecutive slices, each small enough that its matrix holds about 8 million values (but at least 64 origins) when an origin has values_per_origin of them: destinations, times percentiles for a travel-time matrix; destinations times departure minutes (times draws) for an expanded matrix.

Source

pub fn write_street_matrix( &self, first_origin: usize, m: &StreetMatrix, percentiles: &[i32], ) -> Result<()>

A street travel-time matrix: from_id, to_id and one travel_time_pXX column per percentile (the street time repeated in each), one row per destination reached. percentiles are the column names’ numbers, in order.

Source

pub fn write_transit_matrix( &self, first_origin: usize, m: &TransitMatrix, ) -> Result<()>

A walk + transit travel-time matrix: from_id, to_id and one travel_time_pXX column per percentile, one row per destination whose lowest percentile is reported, empty where there is no time.

Source

pub fn write_expanded( &self, first_origin: usize, m: &ExpandedMatrix, breakdown: bool, ) -> Result<()>

An expanded or arrival matrix: from_id, to_id, departure_time (HH:MM:SS), draw_number, with breakdown the five partial times, then routes, with breakdown n_rides, and total_time; the trip’s fields are empty where there is no trip.

Source

pub fn write_accessibility( &self, first_origin: usize, a: &Accessibility, opportunities: &[String], ) -> Result<()>

Accessibility: id, opportunity, percentile, cutoff and accessibility, one row per opportunity column (named by opportunities, in the columns’ order), percentile and cutoff.
