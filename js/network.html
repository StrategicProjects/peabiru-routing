peabiru for JavaScript

Inspecting a network

These functions read a network without routing on it: where points snap to the streets, the area the streets cover, the street and public transport networks as GeoJSON, and the dates with service. Each returns a Promise.

const network = await peabiru.buildNetwork({
  pbf: await readFile("spo_osm.pbf"),
  gtfs: [{ name: "spo_gtfs.zip", data: await readFile("spo_gtfs.zip") }],
});
const points = parsePoints(await readFile("spo_points.csv", "utf8"));

Sizes and versions

network.info() gives the sizes of a network (synchronously):

console.log(network.info());
console.log(await network.transitAvailability("2019-05-13"));
console.log("warnings of the build:", network.buildWarnings().length);
console.log("workers:", network.workers);

vertices and edges count every vertex and directed edge of the street network, including the connectors of transit stops; elevation is the slope cost function (see Elevation); feeds the GTFS feed ids, in loading order; stops, patterns (trip patterns) and services the sizes of the public transport network; frequencies whether any trip is frequency-based. network.buildWarnings() lists the warnings of the build (about the elevation raster), and network.workers the number of workers.

Where points snap

findSnap() gives, for each point, the nearest point of a street that the mode ("WALK" by default, "BICYCLE" or "CAR") may use, first within 300 metres and then within radius (1600 metres by default). A point that does not snap is not routed.

const three = { id: points.id.slice(0, 3), lon: points.lon.slice(0, 3), lat: points.lat.slice(0, 3) };
const snap = await peabiru.findSnap(network, three, { mode: "CAR" }); // radius: 1600 m by default
for (let i = 0; i < snap.point_id.length; i++) {
  console.log(snap.point_id[i], snap.found[i], snap.snap_lon[i], snap.snap_lat[i], `${snap.distance[i].toFixed(1)} m`);
}

89a8100c007ffff true -46.6320409 -23.5581859 53.7 m
89a8100c077ffff true -46.6288723 -23.5532517 0.8 m

The columns are point_id, lat, lon, snap_lat, snap_lon, distance (metres, haversine on a sphere of radius 6,367,450 m) and found; snap_lat, snap_lon and distance are NaN where a point does not snap.

The bounding box

streetNetworkBbox() gives the envelope of the street network, which covers every OpenStreetMap node of the ways the streets were made from: as a GeoJSON Polygon ("polygon", the default), a GeoJSON bbox [xmin, ymin, xmax, ymax] ("bbox") or an object ("vector").

console.log(await peabiru.streetNetworkBbox(network, "vector"));
console.log(await peabiru.streetNetworkBbox(network, "bbox")); // a GeoJSON bbox
const box = await peabiru.streetNetworkBbox(network); // a GeoJSON Polygon
console.log(box.type, box.coordinates[0].length, "points");

The street network

streetNetworkToSf() gives two GeoJSON FeatureCollections: vertices, the Points at the ends of street edges (with index, park_and_ride and bike_sharing, always false), and edges, one LineString per directed street edge, the connectors of transit stops and park-and-rides left out:

const { vertices, edges } = await peabiru.streetNetworkToSf(network);
console.log(vertices.features.length, "vertices,", edges.features.length, "directed edges");
console.log(edges.features[0].properties);

The public transport network

transitNetworkToSf() gives stops (a Point per stop, with stop_index, stop_id prefixed by the feed id, stop_name and linked_to_street; a stop not linked to the streets has a null geometry) and routes, one feature per trip pattern, with agency_id, agency_name, route_id, long_name, short_name and mode. A route’s line is the GTFS shape of the trip that made the pattern or, without one, the positions of its linked stops; patterns without a line are left out, and a line whose points are all the same is a Point.

const { stops, routes } = await peabiru.transitNetworkToSf(network);
console.log(stops.features.length, "stops,", routes.features.length, "routes (one per trip pattern)");
console.log(stops.features[0].properties);
console.log(routes.features[0].properties, routes.features[0].geometry.type);

Dates with service

checkTransitAvailability() counts the services active on each date: given as dates ("YYYY-MM-DD" strings or Dates, read in local time), as a range from startDate to endDate, or, with neither, the dates on which some trip runs, found from the network. total_services counts every service of the feeds, used by trips or not. The routing functions make the same check on the departure date: none active is an error, fewer than 20% a warning.

const week = await peabiru.checkTransitAvailability(network, { startDate: "2019-05-12", endDate: "2019-05-18" });
for (let i = 0; i < week.date.length; i++) {
  console.log(week.date[i], `${week.active_services[i]} of ${week.total_services[i]} services`, week.pct_active[i]);
}
// with no dates: every date on which some trip runs
const all = await peabiru.checkTransitAvailability(network);
console.log(all.date.length, "dates, from", all.date[0], "to", all.date[all.date.length - 1]);

GTFS errors

GTFS feeds are checked when a network is built, with the checks of the validator gtfs-lib (Conveyal). getGtfsErrors() reads the feeds again and returns the errors, one row per error, feed by feed in the order gtfs-lib finds them: file (the table, without .txt), line (the record, the header being line 1; 0 for a whole table), type (gtfs-lib’s class of error), field, id (the key concerned, for duplicate keys and suspect stop locations) and priority ("HIGH", "MEDIUM", "LOW" or "UNKNOWN"). A Network does not keep its feeds, so pass them as buildNetwork() takes them:

const gtfs = [{ name: "spo_gtfs.zip", data: await readFile("spo_gtfs.zip") }];
const errors = await peabiru.getGtfsErrors(gtfs); // the feeds, as buildNetwork() takes them
console.log(Object.keys(errors));
for (let i = 0; i < 3; i++) {
  console.log(errors.file[i], errors.line[i], errors.type[i], errors.field[i], errors.id[i], errors.priority[i]);
}
console.log(errors.priority.filter((p) => p === "HIGH").length, "errors of priority HIGH");

buildNetwork() refuses feeds with errors of priority HIGH: it rejects with an Error that names each feed and its number of such errors, and getGtfsErrors() on the same feeds tells which they are. Errors of lower priority do not stop the build.

// a small feed made up here, with no agency.txt
const bus = storedZip({
  "stops.txt": "stop_id,stop_name,stop_lat,stop_lon\nA,A,-23.5563,-46.6290\nB,B,-23.5577,-46.6321\n",
  "routes.txt": "route_id,route_type\nR,3\n",
  "trips.txt": "route_id,service_id,trip_id\nR,S,T1\n",
  "stop_times.txt": "trip_id,arrival_time,departure_time,stop_id,stop_sequence\nT1,14:00:00,14:00:00,A,1\nT1,14:05:00,14:05:00,B,2\n",
  "calendar.txt": "service_id,monday,tuesday,wednesday,thursday,friday,saturday,sunday,start_date,end_date\nS,1,1,1,1,1,1,1,20190101,20191231\n",
});
const feeds = [...gtfs, { name: "bus.zip", data: bus }];
try {
  await peabiru.buildNetwork({ pbf: await readFile("spo_osm.pbf"), gtfs: feeds });
} catch (e) {
  console.log(`${e.name}: ${e.message}`);
}
const found = await peabiru.getGtfsErrors(feeds);
const high = found.priority.map((p, i) => (p === "HIGH" ? `${found.file[i] ?? "(feed)"}: ${found.type[i]}` : null)).filter(Boolean);
console.log(high);

Error: High priority GTFS errors found; network build failed (bus.zip: 1 error). Use getGtfsErrors() on the same feeds to see them.

When gtfs-lib fails on a feed instead of listing errors, getGtfsErrors() rejects with an Error naming the cause. GTFS-Flex zones (locations.geojson) and location groups are read as gtfs-lib reads them, for its errors; on-demand trips are not routed.
