peabiru for JavaScript

API reference

Everything the package exports, from its type declarations (lib/index.d.ts, generated into this page when the site is built). The functions that read or route on a network return a Promise; options are the fields of an options object.

The examples assume this setup, on the São Paulo sample of the Python package (node site/js/run_examples.mjs runs each of them after it):

import { readFile } from "node:fs/promises";
import * as peabiru from "peabiru";

const pbf = await readFile("spo_osm.pbf");
const gtfs = [{ name: "spo_gtfs.zip", data: await readFile("spo_gtfs.zip") }];
const network = await peabiru.buildNetwork({ pbf, gtfs });
// three points of the sample, with the number of jobs at each
const points = {
  id: ["a", "b", "c"],
  lon: [-46.6290, -46.6321, -46.6355],
  lat: [-23.5563, -23.5577, -23.5601],
  jobs: [153, 551, 120],
};

Networks

buildNetwork

function

export declare function buildNetwork(input: BuildNetworkInput): Promise<Network>;

Build a transport network from an OpenStreetMap extract, zero or more GTFS feeds and an optional elevation raster, given as the bytes of the files. Loads the WebAssembly module first if needed. Rejects when a file cannot be read, and when a GTFS feed has errors of priority HIGH.

const net = await peabiru.buildNetwork({ pbf, gtfs, nThreads: 2 });
console.log(net.info(), net.workers);
net.free();

The feeds load in array order, and nothing is written to disk.

BuildNetworkInput

interface

export interface BuildNetworkInput

The input of buildNetwork().

  • pbf: Bytes: The OpenStreetMap extract: the bytes of a .pbf file.
  • gtfs?: GtfsFeed[]: The GTFS feeds, loaded in this order (default: none, a street network only). A feed with errors of priority HIGH (see getGtfsErrors()) is refused: the build rejects with an Error naming it.
  • tif?: Bytes: An elevation raster, the bytes of a GeoTIFF file (default: none): walking and cycling times then get the slope costs of elevation. One band, north up, uncompressed or compressed with LZW, Deflate or PackBits, in WGS 84 longitude and latitude (EPSG:4326), SIRGAS 2000 (4674), SAD69 (4618), Corrego Alegre (4225), their UTM zones used in Brazil, SIRGAS 2000 / Brazil Polyconic (5880), WGS 84 / UTM (326xx, 327xx) or Pseudo-Mercator (3857); other rasters are an error. Voids and values beyond +/-3276.7 m are stored wrapped around, as 16-bit decimetres, with a warning; in a projected raster, a street point within nanometres of a pixel boundary reads the same pixel on every machine, with a warning. With a raster, travelTimeMatrix() never routes walking trips from the destinations.
  • elevation?: string: The slope cost function when tif is given: "TOBLER" (default, Tobler’s hiking function), "MINETTI" (Minetti’s energy cost of walking) or "NONE", in any case. Without tif it is "NONE".
  • onWarning?: WarningHandler: Receives the warnings of the build (about the raster); by default console.warn.
  • nThreads?: number | null: Workers to route on. 1 (default): no workers, everything runs on the calling thread. A whole number above 1: a pool of that many workers (Web Workers in browsers, worker_threads in Node), each holding its own copy of the network, all built at once. 0, null or Infinity: one worker per core (navigator.hardwareConcurrency, or Node’s os.availableParallelism()). Each worker costs about the memory of a network built on the calling thread.
  • useWorkers?: boolean: Route in workers even with one thread, so that a call never blocks the calling thread and can be aborted (default: true when nThreads is given and is not 1, else false; must not be false with more than one thread).

GtfsFeed

interface

export interface GtfsFeed

One GTFS feed: the .zip file’s name and its bytes.

  • name: string: The file name, such as "poa_eptc.zip". It names the feed in messages and, when the feed has no feed_info.feed_id, gives its feed id (the name without .zip), which prefixes its stop ids. Names must be distinct.
  • data: Bytes: The bytes of the .zip file.

type

Bytes of a file.

WarningHandler

type

export type WarningHandler = (message: string) => void;

Receives each warning, as a string; by default console.warn.

Network

class

export declare class Network

A transport network: the street network and, when GTFS feeds were given, the public transport layer, held in the memory of the WebAssembly module (or, for a network with workers, in each worker) until free(). Built by buildNetwork(); it cannot be sent to another Worker (build it there).

console.log(network.info().stops, "stops,", network.workers, "workers");
console.log(await network.transitAvailability("2019-05-13"));
network.free();
  • free(): void: Release the network’s memory and stop its workers; calls still running on them reject. The network cannot be used afterwards. In Node, idle workers do not keep a program alive, so a program may also end without calling it.
  • readonly workers: number: Number of workers of the network; 0 when it routes on the calling thread.
  • info(): NetworkInfo: The sizes of the network (see NetworkInfo).
  • transitAvailability(date: Date | string): Promise<{ services: number; active: number }>: The number of services in the network and of those running on date (a Date, read in local time, or a string "YYYY-MM-DD"): the check the routing functions make on their departure date.
  • buildWarnings(): string[]: The warnings of the build, which buildNetwork() also hands to onWarning: those about the elevation raster (samples stored wrapped around, beyond +/-3276.7 m, such as SRTM’s -32768 voids, or equal to the raster’s no-data value; street points near a pixel boundary of a projected raster).

NetworkInfo

interface

export interface NetworkInfo

Sizes of a network, from network.info().

  • vertices: number: Street vertices, including those of the connectors of transit stops.
  • edges: number: Directed street edges, including the connectors of transit stops.
  • elevation: string: The slope cost function in use: "TOBLER", "MINETTI" or "NONE".
  • feeds: string[]: The GTFS feed ids, in loading order.
  • stops: number: Transit stops.
  • patterns: number: Trip patterns.
  • services: number: GTFS services (calendars).
  • frequencies: boolean: Whether any trip is frequency-based.

Travel-time matrices

travelTimeMatrix

function

export declare function travelTimeMatrix(
  network: Network,
  origins: Points,
  destinations: Points,
  options?: TravelTimeMatrixOptions,
): Promise<TravelTimeMatrix>;

Travel times between every origin and every destination: on the streets by one mode, or by public transport with the percentiles of the travel times over the departure window (and, for frequency-based trips, over the Monte Carlo draws). Every option is in TravelTimeMatrixOptions and RoutingOptions. Pairs not reached within maxTripDuration are left out.

const ttm = await peabiru.travelTimeMatrix(network, points, points, {
  mode: ["WALK", "TRANSIT"],
  departureDatetime: "2019-05-13 14:00:00",
  percentiles: [25, 50, 75],
  seed: 42,
});
console.log(ttm.from_id[1], ttm.to_id[1], ttm.travel_time_p50[1]);

TravelTimeMatrixOptions

interface

export interface TravelTimeMatrixOptions extends RoutingOptions

Options of travelTimeMatrix().

Also takes every option of RoutingOptions.

  • departureDatetime?: DateTime | null: Required with public transport; the current time otherwise (default null).
  • timeWindow?: number: Minutes of departure times, from departureDatetime on (default 10).
  • percentiles?: number | number[]: 1 to 5 distinct whole numbers from 1 to 99 (default 50): the percentiles of the travel times over the window.
  • fareStructure?: FareStructure | null: A fare structure (see setupFareStructure()), or null (default): no fares. With one, public transport is routed with the multi-criteria router (McRAPTOR) over timeWindow * drawsPerMinute sampled departure times.
  • maxFare?: number: The highest fare of a trip (default Infinity); a finite value needs a fareStructure.

TravelTimeMatrix

interface

export interface TravelTimeMatrix

Columns of a travel-time matrix: one row per origin and destination reached, origin-major in input order. travel_time_pXX (one per percentile, ascending, two digits: travel_time_p05) holds whole minutes, NA_INT32 where a percentile is not reached.

  • from_id: (string | null)[]
  • to_id: (string | null)[]
  • [travelTime: `travel_time_p${string}`]: Int32Array

Accessibility

accessibility

function

export declare function accessibility(
  network: Network,
  origins: Points,
  destinations: Points,
  options?: AccessibilityOptions,
): Promise<AccessibilityTable>;

Access to opportunities from each origin: the opportunities of the destinations (the columns opportunitiesColnames), weighted by a decay function of the travel time to them and summed. Every option is in AccessibilityOptions, TravelTimeMatrixOptions and RoutingOptions.

const access = await peabiru.accessibility(network, points, points, {
  opportunitiesColnames: "jobs",
  mode: "WALK",
  cutoffs: [10, 20],
});
console.log(access.id, access.cutoff, access.accessibility);

AccessibilityOptions

interface

export interface AccessibilityOptions extends TravelTimeMatrixOptions

Options of accessibility().

Also takes every option of TravelTimeMatrixOptions.

  • opportunitiesColnames?: string | string[]: Opportunity columns of the destinations (default "opportunities"). Missing values count as 0, with a warning.
  • decayFunction?: "step" | "exponential" | "fixed_exponential" | "linear" | "logistic": "step" (default), "exponential", "fixed_exponential", "linear" or "logistic".
  • cutoffs?: number | number[] | null: 1 to 12 distinct whole minutes from 1 to 120: the cutoffs of "step", and for the other functions the travel time at which the weight is one half; null (default) only with "fixed_exponential", which takes none.
  • decayValue?: number | null: The decay constant ("fixed_exponential", between 0 and 1), the width in whole minutes ("linear", 1 to 59) or the standard deviation in minutes ("logistic", at least 1); null (default) otherwise.

AccessibilityTable

interface

export interface AccessibilityTable

Columns of an accessibility table: one row per origin, opportunity, percentile and cutoff, in that order. No cutoff with "fixed_exponential".

  • id: (string | null)[]
  • opportunity: string[]
  • percentile: Int32Array
  • cutoff?: Int32Array
  • accessibility: Float64Array

export declare function expandedTravelTimeMatrix(

Detailed itineraries

detailedItineraries

function

export declare function detailedItineraries(
  network: Network,
  origins: Points,
  destinations: Points,
  options?: DetailedItinerariesOptions,
): Promise<{ type: "FeatureCollection"; features: ItineraryFeature[] } | ItineraryRow[]>;

The legs of the trips between pairs of origins and destinations: each walk, ride by bicycle or car and public transport ride, with its duration, wait, distance, route and line. Each pair gets its fastest itinerary over the departure window (the trip by the street mode alone, or by public transport, whichever is faster) or, with shortestPath: false, the alternatives found by the multi-criteria router (McRAPTOR). One row per leg, as a GeoJSON FeatureCollection or, with dropGeometry, an array of rows; pairs without an itinerary have none. Every option is in DetailedItinerariesOptions and RoutingOptions. Public transport needs feeds with timetables: a network with frequency-based trips is an error. With modeEgress: "CAR", a pair whose egress crosses a turn restriction with two or more via ways, which can be read in either order, always gets the itinerary of a freshly built network routing that pair alone, with a warning.

const back = { id: [...points.id].reverse(), lon: [...points.lon].reverse(), lat: [...points.lat].reverse() };
const legs = await peabiru.detailedItineraries(network, points, back, {
  mode: "BICYCLE",
  departureDatetime: "2019-05-13 14:00:00",
  dropGeometry: true,
});
console.log(legs.map((r) => `${r.from_id} > ${r.to_id}: ${r.total_duration} min, ${r.total_distance} m`));

DetailedItinerariesOptions

interface

export interface DetailedItinerariesOptions extends Omit<RoutingOptions, "drawsPerMinute" | "seed">

Options of detailedItineraries().

  • departureDatetime?: DateTime | null: Required with public transport; the current time otherwise.
  • timeWindow?: number: Minutes of departure times, from departureDatetime on (default 10).
  • suboptimalMinutes?: number: With shortestPath: false, how many minutes after the best arrival at a stop the multi-criteria search still keeps a state there, which widens the set of alternatives (default 0). Must be 0 with shortestPath: true or a fareStructure.
  • shortestPath?: boolean: Only the fastest itinerary of each pair (default true); false gives the alternatives, one per sequence of routes.
  • allToAll?: boolean: Route from every origin to every destination (default false: pair them row by row, a single origin or destination repeated to match the other).
  • fareStructure?: FareStructure | null: A fare structure (default null): trips routed with fares, and fare columns in the result.
  • maxFare?: number: The highest fare of a trip (default Infinity); a finite value needs a fareStructure.
  • dropGeometry?: boolean: Plain rows instead of GeoJSON features (default false).
  • osmLinkIds?: boolean: Add the properties osm_id_list, edge_id_list, board_stop_id and alight_stop_id to each row (default false; needs dropGeometry: false): see ItineraryRow.

ItineraryRow

interface

export interface ItineraryRow

One leg of an itinerary: durations and waits are minutes with one decimal, distances metres; route is the GTFS route_id of a ride, empty for a street leg.

  • from_id: string | null
  • from_lat: number
  • from_lon: number
  • to_id: string | null
  • to_lat: number
  • to_lon: number
  • option: number: The itinerary of the pair, from 1.
  • departure_time: string: "HH:MM:SS", when the itinerary leaves the origin.
  • total_duration: number
  • total_distance: number
  • total_fare?: number: With a fare structure only.
  • segment: number: The leg, from 1.
  • mode: string: "WALK", "BICYCLE", "CAR", or the mode of a ride, such as "BUS".
  • cumulative_fare?: number: With a fare structure only: the fare paid up to the end of the leg.
  • segment_duration: number
  • wait: number
  • distance: number
  • route: string
  • osm_id_list?: string: With osmLinkIds: the OpenStreetMap way ids of a street leg’s edges, as "[id1, id2, ...]" ("[]" for a ride; consecutive edges on a roundabout give only their first ids, connectors none).
  • edge_id_list?: string: With osmLinkIds: the indices of those edges in the street network (edge_index of streetNetworkToSf()), as "[i1, i2, ...]".
  • board_stop_id?: string: With osmLinkIds: a ride’s boarding stop, "<feed>:<stop_id>"; empty for street legs.

FareStructure

interface

export interface FareStructure

A fare structure: the global settings, three tables as objects of columns, and the debug settings. Made by setupFareStructure() or read by readFareStructure(), and changed by editing its columns.

  • max_discounted_transfers: number | null: Most transfers with a discount (default 1; null for none).

  • fare_cap: number: Highest fare of a trip (Infinity: no cap).

Facility location

locateFacilities

function

export declare function locateFacilities(
  network: Network | null,
  demand: Points,
  candidates: Points,
  options?: LocateFacilitiesOptions,
): Promise<FacilityLocation>;

Where to open new facilities: among the candidate sites, the ones that serve the demand points best, by maximal covering, location set covering, p-median or p-center. The travel times from every demand point to every site come from travelTimeMatrix() with the routing options given, or from travelTimes. The existing facilities count first: only the demand they leave uncovered, or the travel time they leave, drives the choice.

The models are solved by a greedy construction followed by vertex substitution: good and reproducible solutions, not proven optimal. The solver runs on the calling thread. See the guide “Facility location”.

// one new facility among the points, to cover the most jobs within 10 minutes on foot
const found = await peabiru.locateFacilities(network, points, points, {
  model: "max_cover", nFacilities: 1, cutoff: 10, demandColname: "jobs", mode: "WALK",
});
console.log(found.sites.id, found.summary.covered / found.summary.total_demand);

LocateFacilitiesOptions

interface

export interface LocateFacilitiesOptions extends LocationRoutingOptions

Options of locateFacilities().

Also takes every option of LocationRoutingOptions.

  • existing?: Points | null: The facilities already open (default: none). Their ids may not repeat those of the candidates.
  • model?: "max_cover" | "set_cover" | "p_median" | "p_center": "max_cover" (default), "set_cover", "p_median" or "p_center".
  • nFacilities?: number: How many new facilities to open (default 1). Fewer come back when no further site improves the objective. Ignored by "set_cover".
  • cutoff?: number | null: The service standard of the covering models, in minutes: a point is covered by a site at most this far (the cutoff included). Required by "max_cover" and "set_cover"; null for the others.
  • demandColname?: string | null: The column of the demand points with their weights (residents, pupils…), finite and not negative; null (default) for 1 each.
  • percentile?: number: The travel-time percentile used, 1 to 99 (default 50).

floatingCatchment

function

export declare function floatingCatchment(
  network: Network | null,
  demand: Points,
  supply: Points,
  options?: FloatingCatchmentOptions,
): Promise<FloatingCatchment>;

Supply against demand around each place, by the two-step floating catchment area: the supply of each facility is divided by the demand within its catchment, and each demand point adds up the ratios of the facilities within its catchment. With a decay function other than "step", nearer pairs weigh more in both steps. The sum of demand times accessibility equals the supply of the facilities that have any demand in their catchment. See the guide “Facility location”.

  cutoff: 20, demandColname: "jobs", supplyColname: "places", mode: "WALK",
});
console.log(fca.demand.id, fca.demand.accessibility);

isochrone

function

export declare function isochrone(
  network: Network,
  origins: Points,
  options: IsochroneOptions & { polygonOutput: false },

export declare function isochrone(
  network: Network,
  origins: Points,

The areas, or the street segments, reached from each origin within each cutoff. With polygonOutput: true (the default), one MultiPolygon feature per origin, percentile (ascending) and cutoff (descending), empty when nothing is reached, made by interpolating the travel times on a Web Mercator grid (zoom) and tracing their contours with isoband’s algorithm; with polygonOutput: false, one LineString per street segment reached, by origin, then band and travel time descending.   cutoffs: [5, 10],
});
console.log(iso.features.map((f) => `${f.properties.id} ${f.properties.isochrone} min`));

The polygons are always MultiPolygons, as the contouring (a port of isoband) gives them: not repaired and not snapped to 1e-7 degrees, with the same rings on every platform.

Default null: all four with a fareStructure, all but "FARE" without one.
  • maxOptions?: number: At most this many options per pair, the first in option order (default Infinity).
  • walkResolution?: number: Seconds to which minutes on foot are compared (default 60: the whole minute, rounded), so that of two trips a few seconds of walking apart and otherwise no better only one is returned; 1 compares the exact seconds.
  • allToAll?: boolean: Route from every origin to every destination (default false: pair them row by row).
  • itineraries?: boolean: Build the legs of each option (default true).
  • byDeparture?: boolean: Add the options of every departure minute (default false).
  • fareStructure?: FareStructure | null: A fare structure (default null): needed for the "FARE" criterion, gives every option its fare.
  • maxFare?: number: The highest fare of a trip (default Infinity).
  • dropGeometry?: boolean: Plain rows for the legs instead of GeoJSON features (default false).
  • osmLinkIds?: boolean: Add the osm_link_ids properties to each leg (default false), as in detailedItineraries().

tripOptions

function

export declare function tripOptions(
  network: Network,
  origins: Points,
  destinations: Points,
  options?: TripOptionsOptions,
): Promise<TripOptions>;

A multi-criteria trip planner: for each origin-destination pair, the trips that no other trip beats on all the chosen criteria at once, at each departure minute of the window, merged into options. Frequency-based routes are boarded at their expected times (half a headway): no random draws. See the guide “Trip options”.

const res = await peabiru.tripOptions(network, { id: ["a"], lon: [-46.6290], lat: [-23.5563] },
  { id: ["c"], lon: [-46.6355], lat: [-23.5601] }, {
    departureDatetime: "2019-05-13 14:00:00", timeWindow: 3, itineraries: false,
  });
console.log(res.options.map((o) => `${o.total_time} min, ${o.walk_time} on foot: ${o.description}`));
