    API reference¶

    All functions are available at the top level of the package (import peabiru).

    Networks¶

    build_network ¶

    build_network(data_path: PathLike, verbose: bool = False, temp_dir: bool = False, elevation: str = 'TOBLER', overwrite: bool = False, n_threads: Optional[Union[int, float]] = math.inf) -> Network

    Build a transport network.

    Builds a multimodal transport network from a directory with one OpenStreetMap extract (.pbf) and zero or more GTFS feeds (.zip), and optionally an elevation raster (.tif). The network lives in memory and is reused by every routing function; nothing is written to data_path. The files are recognised by their extension in lower case only: a map.PBF or a feed.ZIP is ignored.

    A .tif raster in data_path gives walking and cycling times slope costs (elevation="TOBLER", the default, or "MINETTI"; never for cars): the raster is sampled every 10 m along each street at the nearest pixel, and each street's time is multiplied by the average cost of its slopes. Points outside the raster count as 0 m high. Without a .tif raster the network is built with elevation="NONE".

    The raster must be a GeoTIFF with one band, north up, uncompressed or compressed with LZW, Deflate or PackBits (what GDAL writes by default), in WGS 84 longitude and latitude (EPSG:4326) or in another coordinate reference system whose transform peabiru reproduces exactly, given by its EPSG code (what GDAL writes): SIRGAS 2000 (4674), SAD69 (4618), Corrego Alegre 1970-72 (4225), their UTM zones used in Brazil (31965-31985, 6210, 6211, 5396; 29168-29172, 29187-29195; 22521-22525), SIRGAS 2000 / Brazil Polyconic (5880), WGS 84 / UTM (32601-32660, 32701-32760) and WGS 84 / Pseudo-Mercator (3857). Other rasters are an error that says what to change, and so are a .prj file next to the raster, a raster whose name ends in .tiff and more than one raster.

    In a projected system, a street point within nanometres (5e-8 m, or 2e-13 degrees) of the boundary between two pixels of different values, or of the raster's edge, reads the pixel that peabiru's own sines and cosines give, the same on every machine, and a UserWarning gives the number of such points (about one in a hundred million for 30 m pixels; reprojecting the raster to EPSG:4326 removes the ambiguity). A point that falls on the raster's outer edge (inside its envelope, past the last pixel) is an error: there is no pixel to read. Elevations are kept in decimetres in 16-bit integers, so voids and values beyond +/-3276.7 m wrap around (SRTM's -32768 voids become 0 m, -9999 becomes 3108.2 m, a NaN no-data value becomes 0 m); a UserWarning counts them and the samples equal to the raster's no-data value. A routing call with a scenario (new_carspeeds, carspeed_scale, new_lts) on a network with elevation runs without the slope costs, with a warning. See Elevation.

    The GTFS feeds are loaded in the order in which the operating system lists the directory. With more than one feed that order depends on the file system, so the same directory can give slightly different expanded and arrival matrices on two machines (another stop or route for a few trips); on one machine the results are always the same.

    The network is not built when a GTFS feed has errors of priority "HIGH" (a reference to a stop, route, trip, service or agency that does not exist, a number that cannot be read, tables in a subfolder of the .zip, routes without any agency): the RuntimeError names the feeds and points to get_gtfs_errors(), which lists the errors. A feed that cannot be loaded at all is an error too.

    		 "TOBLER"

    Returns:

    Type Description

    Raises:

    Type Description

    Network ¶

    A transport network built by build_network().

    It holds the street network and, when the data directory had GTFS feeds, the public transport layer, in memory. Pass it to the routing functions. It cannot be pickled: build it again in each process (it takes seconds even for a whole city).

    Attributes:

    Name Type Description
    data_path str

    The directory the network was built from.
    elevation str

    The slope cost function in use: "TOBLER", "MINETTI" or "NONE" (also when the directory has no .tif raster).
    has_tif bool

    Whether the directory has a .tif raster. Walking matrices with more origins than destinations are routed from the destinations (and the columns swapped back), except when it has one.

    Examples:

    >>> import peabiru
>>> network = peabiru.build_network(peabiru.sample_data_path(), n_threads=2)
>>> network.elevation, network.has_tif
('NONE', False)

    Travel-time matrix between origins and destinations.

    Travel times between every origin and every destination, by one street mode ("WALK", "BICYCLE" or "CAR") or by public transport (all of it or some of its modes, reached and left on foot, by bicycle or by car). With public transport, the travel time from an origin to a destination is computed for every departure minute of the time window (and every Monte Carlo draw with frequency-based GTFS), and the result reports percentiles of those times.

    A bicycle or car trip to public transport goes on on foot from wherever the vehicle got, within the same max_bike_time or max_car_time, and the trip without public transport keeps those walking ends too. Egress by bicycle or car is searched from every stop with fixed limits (up to 5 km by bicycle at any level of traffic stress, up to 30 minutes by car) and must stay within max_bike_time or max_car_time.

    Access to opportunities.

    locate_facilities ¶

    locate_facilities(network: Any, demand: Any, candidates: Any, existing: Any = None, model: str = 'max_cover', n_facilities: Any = 1, cutoff: Any = None, demand_colname: Optional[str] = None, mode: Any = 'WALK', mode_egress: str = 'WALK', departure_datetime: Optional[Any] = None, percentile: Any = 50, max_trip_duration: Any = None, travel_times: Any = None, swap: bool = True, min_gain: Any = 0, unreachable_time: Any = None, n_threads: Any = None, **routing: Any) -> FacilityLocation

    Where to open new facilities.

    Chooses, among the candidate sites, where to open facilities so that the demand points are served best, by one of four classic location models. The travel times from every demand point to every site are computed with travel_time_matrix() (or taken from travel_times), so any mode, departure time and routing option of the matrix applies.

    The models:

    • "max_cover", maximal covering: with n_facilities new facilities, cover the most demand within cutoff minutes.
    • "set_cover", location set covering: the fewest new facilities that leave every demand point within cutoff minutes of one (every point some site can cover; the others are reported).
    • "p_median": n_facilities new facilities with the smallest demand-weighted sum of travel times to the nearest facility.
    • "p_center": n_facilities new facilities with the smallest travel time for the demand point farthest from its nearest facility.

    The existing facilities are already open and count first: only the demand they leave uncovered, or the travel time they leave, drives the choice of the new sites.

    The models are solved by heuristics: a greedy construction (each site the one that improves the objective most, given the ones before it) followed, with swap, by vertex substitution (swap an open new site for a closed candidate while that improves the objective). The solution is good and reproducible, not proven optimal; for maximal covering the greedy solution covers at least 63% (1 - 1/e) of the most that could be covered of the demand not yet covered. Ties go to the candidate listed first, and the result does not depend on n_threads. See the guide Facility location.

    Supply against demand around each place: the two-step floating catchment area.

    Step 1: the supply of each facility (places, staff, beds) is divided by the demand within its catchment. Step 2: each demand point adds up the ratios of the facilities within its catchment.     transit_network_to_sf ¶

    transit_network_to_sf(network: Network) -> Dict[str, Any]

    The public transport network as GeoDataFrames.

    The stops and the routes of the public transport layer.     get_gtfs_errors ¶

    get_gtfs_errors(network: Union[Network, PathLike]) -> pd.DataFrame

    The errors gtfs-lib reports in the network's GTFS feeds.

    The errors that the validator gtfs-lib (Conveyal) reports when it reads the feeds, with every check of gtfs-lib's table loaders and of its post-load validation. build_network() refuses feeds with errors of priority "HIGH"; this function lists them, from the files a network was built from or from the .zip files of a directory (so it also works on feeds that cannot be built). The feeds are read again on each call; the rows are listed feed by feed, in the order gtfs-lib finds them.

    A feed on which gtfs-lib fails instead of listing errors (a date that is not YYYYMMDD, a frequency of a trip that does not exist, a service or fare without an id, the first or last stop of a trip without a name) raises RuntimeError naming the cause, and so does a locations.geojson of GTFS-Flex zones that is not in UTF-8. GTFS-Flex zones and location groups are read as gtfs-lib reads them, for its errors; on-demand trips are not routed.

    Parameters:

    Name Type Description Default
    network (Network, str or PathLike)

    A network built with build_network(), or a directory with GTFS feeds (.zip).

    		 required

    Returns:

    Type Description
    DataFrame

    file (the table, without .txt), line (the record, the header being line 1; 0 for a whole table), type (gtfs-lib's error class), field and id (None when the error has none) and priority ("HIGH", "MEDIUM", "LOW" or "UNKNOWN").
    Notes

    The feeds are read again at each call, and the rows are listed feed by feed in the order the errors are found, the same in every run. A directory that does not exist is an error.

    Examples:

    >>> import peabiru
>>> network = peabiru.build_network(peabiru.sample_data_path(), n_threads=2)
>>> errors = peabiru.get_gtfs_errors(network)
>>> sorted(set(errors["type"]))
['DuplicateKeyError']
