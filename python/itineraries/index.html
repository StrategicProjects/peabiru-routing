    Detailed itineraries¶

    detailed_itineraries() gives the legs of each trip between pairs of origins and destinations: walking, cycling or driving, and each public transport ride, with its duration, waiting time, distance, route and line.

    The examples use the sample data of Porto Alegre from the r5r project, downloaded once into the temporary directory (about 2 MB); its GTFS feeds only have service in the afternoon, hence the 14:00 departure.

    import datetime as dt
import tempfile
import urllib.request
from pathlib import Path

import pandas as pd

import peabiru

poa = Path(tempfile.gettempdir()) / "peabiru-poa"
poa.mkdir(exist_ok=True)
url = "https://raw.githubusercontent.com/ipea/r5r/v2.5.0/r-package/inst/extdata/poa/"
for name in ["poa_osm.pbf", "poa_eptc.zip", "poa_trensurb.zip", "poa_points_of_interest.csv"]:
    if not (poa / name).exists():
        urllib.request.urlretrieve(url + name, poa / name)

network = peabiru.build_network(poa)  # a .pbf and GTFS .zip files
points = pd.read_csv(poa / "poa_points_of_interest.csv")  # id, lat, lon

trips = peabiru.detailed_itineraries(
    network, points.iloc[:3], points.iloc[3:6],
    mode=["WALK", "TRANSIT"],
    departure_datetime=dt.datetime(2019, 5, 13, 14, 0),
)
print(trips.drop(columns=["from_lat", "from_lon", "to_lat", "to_lon", "geometry"]).to_string())

    Origins and destinations are paired row by row (a single origin or destination is repeated to match the other); all_to_all=True routes every origin to every destination. Each pair gets its fastest itinerary (shortest_path=True): the trip by the street mode alone, or the fastest public transport trip over the departure window, whichever is faster. Pairs without one have no rows.

    The result is a geopandas.GeoDataFrame of LineStrings in EPSG:4326, one row per leg (segment), or a pandas.DataFrame with drop_geometry=True. Of note:

    • a street leg's line holds the whole of the first and last street segments, not only the parts walked or driven; the leg from the last stop ends at the destination itself;
    • a ride follows the GTFS shape of its trip pattern, or straight lines between stops when the feed has no shapes;
    • a walk between stops is routed again on the streets for its line and distance; its duration is the one public transport routing used.

    Alternatives¶

    With shortest_path=False, each pair gets, besides the trip by the street mode alone, the alternatives the multi-criteria router (McRAPTOR) finds over the departure window, one per sequence of routes. suboptimal_minutes (which must be 0 with shortest_path=True) keeps search branches up to that many minutes slower than the best one, so higher values return more itineraries. The options are numbered by option in this order: the trip by the street mode alone first, then by the number of legs, then by duration, so the first option is not the fastest when a trip with fewer legs is slower (on Porto Alegre with suboptimal_minutes=10, a pair had 102 options, the first of 60.4 minutes and the fastest of 53.3):

    def alternatives(minutes):
    return peabiru.detailed_itineraries(
        network, points.iloc[[1]], points.iloc[[4]],
        mode=["WALK", "TRANSIT"],
        departure_datetime=dt.datetime(2019, 5, 13, 14, 0),
        shortest_path=False, suboptimal_minutes=minutes, drop_geometry=True,
    )


for minutes in [0, 1, 5]:
    print(minutes, "minutes:", alternatives(minutes)["option"].nunique(), "options")
print(alternatives(0)[["option", "departure_time", "total_duration", "segment", "mode",
                       "segment_duration", "wait", "route"]].to_string())

    Pairs¶

    Origins and destinations are paired row by row, and a single origin or destination is repeated to match the other, with a warning; with all_to_all=True every origin is routed to every destination. The street examples below use the sample network of Sao Paulo, which is quicker to build:

    import warnings

spo = peabiru.build_network(peabiru.sample_data_path(), n_threads=2)
spo_points = peabiru.sample_points()
pairs = peabiru.detailed_itineraries(
    spo, spo_points.iloc[:3], spo_points.iloc[3:6], mode="WALK",
    drop_geometry=True, n_threads=2,
)
every = peabiru.detailed_itineraries(
    spo, spo_points.iloc[:3], spo_points.iloc[3:6], mode="WALK",
    all_to_all=True, drop_geometry=True, n_threads=2,
)
with warnings.catch_warnings(record=True) as caught:
    warnings.simplefilter("always")
    one = peabiru.detailed_itineraries(
        spo, spo_points.iloc[:1], spo_points.iloc[3:6], mode="WALK",
        drop_geometry=True, n_threads=2,
    )
def n_pairs(trips):
    return len(trips[["from_id", "to_id"]].drop_duplicates())


print(n_pairs(pairs), "pairs;", n_pairs(every), "with all_to_all;", n_pairs(one), "from one origin")
print(caught[0].message)

    3 pairs; 9 with all_to_all; 3 from one origin
'origins' was expanded to match the number of destinations.

    The streets of each leg¶

    With osm_link_ids=True (which needs the geometry, so not with drop_geometry=True), each street leg also lists the OpenStreetMap ways (osm_id_list) and the edges of the street network (edge_id_list, as street_network_to_sf() numbers them) it goes along, and each ride its board and alight stops (board_stop_id, alight_stop_id, as "<feed>:<stop_id>"). Consecutive edges on a roundabout give only their first ids, and connectors none:

    bike = peabiru.detailed_itineraries(
    spo, spo_points.iloc[[0]], spo_points.iloc[[5]], mode="BICYCLE",
    osm_link_ids=True, n_threads=2,
)
print(bike[["mode", "distance", "osm_id_list"]].to_string())

    Car egress and turn restrictions¶

    With mode_egress="CAR", the egress is searched backwards from the destination, and a turn restriction with two or more via ways can be read in either order of those ways. peabiru fixes the order: every pair gets the itineraries of a freshly built network routing that pair alone with one thread, whatever the other pairs, the threads or the earlier calls, and a warning, once per call, names the pairs whose itineraries the other order of those via ways would change (on Porto Alegre, about 1 pair in 200). Rides along GTFS shapes are cut by shape_dist_traveled where the feed has it. Networks whose GTFS has frequency-based trips cannot be used with public transport here: convert the frequencies to stop times first (with gtfstools' frequencies_to_stop_times() in R, for instance).

    Trip options¶

    To see every trip worth considering between two points, faster or cheaper, with fewer transfers or less walking, and not only the fastest one, see trip_options(), peabiru's own multi-criteria planner: Trip options.
