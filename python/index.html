    peabiru¶

    peabiru computes travel-time matrices and accessibility on multimodal transport networks (walking, cycling, driving and public transport) built from an OpenStreetMap extract and GTFS feeds. It is a Rust port of Conveyal's R5 routing engine.

    Authorship. peabiru is an independent project. Its routing model is that of Conveyal's R5, and its fare calculator and parts of its trip planner are translated from r5r (Ipea); both are MIT-licensed, and their notices are kept in LICENSE-THIRD-PARTY. peabiru is not affiliated with or endorsed by Conveyal, Ipea or the r5r team. The port was written with the assistance of AI coding tools.

    The routing engine is written in Rust and runs inside the Python process: no Java is needed, the network is built once in memory and reused by every call, and results come back as pandas.DataFrames. The same Rust core powers the R package of the same name, with the same functions and arguments. See also the comparison with r5r.

    Function What it computes
    build_network() a network from a directory with one .pbf and any GTFS .zip
    travel_time_matrix() travel times between every origin and destination
    accessibility() cumulative or decay-weighted access to opportunities
    expanded_travel_time_matrix() travel times minute by minute, with a breakdown of each trip
    arrival_travel_time_matrix() the latest trip that arrives by a given time
    isochrone() the areas or street segments reached within each cutoff
    detailed_itineraries() the legs of each trip, with their lines
    setup_fare_structure(), pareto_frontier() transit fares, and the trade-off between travel time and fare
    find_snap(), street_network_to_sf(), ... where points snap, the streets, stops and routes of a network
    get_gtfs_errors() the errors of the GTFS feeds

    Install¶

    peabiru needs Python 3.9 or later; its only required dependency is pandas. Install geopandas as well to pass points as a GeoDataFrame.

    pip install peabiru
pip install "peabiru[geo]"     # with geopandas

    Wheels are built for Linux with glibc (x86_64 and aarch64), macOS (arm64 and x86_64) and Windows (x64). On Linux with musl (Alpine) and on Windows on Arm, pip builds the package from the source distribution, which needs a Rust toolchain (rustc 1.81 or later).

    From a clone of the repository, with a Rust toolchain and maturin:

    cd python
maturin develop --uv --release

    Get started¶

    peabiru ships a small network for examples and tests: the streets around Avenida Paulista, in Sao Paulo, with the frequency-based GTFS feed of SPTrans. Build a network from its directory:

    import peabiru

network = peabiru.build_network(peabiru.sample_data_path(), n_threads=2)
print(network.info())

    {'vertices': 2609, 'edges': 5518, 'elevation': 'NONE', 'feeds': ['spo_gtfs'], 'stops': 654, 'patterns': 36, 'services': 6, 'frequencies': True}

    print(network) shows the same summary, with the data path.

    The network lives in memory and is reused by every routing call. Origins and destinations are pandas.DataFrames with columns id, lon and lat (in WGS 84); the sample comes with 27 points of a hexagonal grid:

    By public transport, leaving at 14:00 on a Monday and over a 10-minute window of departure times, the 25th, 50th and 75th percentiles of the travel time. The sample feed is frequency-based, so the departures are drawn at random: give a seed to make the result reproducible.

    import datetime as dt

ttm = peabiru.travel_time_matrix(
    network, points, points,
    mode=["WALK", "TRANSIT"],
    departure_datetime=dt.datetime(2019, 5, 13, 14, 0),
    percentiles=[25, 50, 75],
    seed=42,
    n_threads=2,
)
print(ttm.iloc[20:25].to_string())

    What peabiru refuses¶

    A request peabiru does not support is an error that says so, never silently ignored: a fare structure that names a fare calculator (a type) instead of fare rules, expanded or arrival matrices by a street mode alone and pareto_frontier() with output_dir raise UnsupportedError; some elevation rasters, more than one .pbf file and a few itinerary pairs are errors too. The guides say where each of them applies.

    Sample data¶

    The sample network in peabiru.sample_data_path() is cut from the Sao Paulo sample data of the r5r project. spo_osm.pbf contains map data © OpenStreetMap contributors, available under the Open Database License; spo_gtfs.zip is a GTFS feed of SPTrans, without shapes.txt.
